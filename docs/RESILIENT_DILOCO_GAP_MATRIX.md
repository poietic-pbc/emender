## Current architecture boundaries

The legacy `train.py` DiLoCo merge and compiled MPICH scale path remain useful numerical/performance references, but their process groups/collectives and launched-rank assumptions are nonconforming for resilient global membership. They must not silently become the resilient protocol. The newer `ndm/resilient_*` modules are the closest implementation scaffold: they establish split roles, fenced generation attempts, bounded chunk spools, point-to-point transport, exact weighted test math, deadlines, replay, and immutable handoff metadata. They are not evidence of a complete compute pool until R01, R02, R07, R11, R15, and R16 close end to end.

Evidence reviewed includes `docs/ASYNC_QUORUM_DILOCO.md` (research precursor), `reports/frontier/true-resilient-e97-node-quorum-20260714.md`, `reports/frontier/implement-true-resilient-progress-20260716.md`, `reports/frontier/resilient-e97-bounded-rank-topology-20260716.md`, `reports/frontier/run-resilient-e97-2-preflight-blocked-20260717.md`, and `reports/cancel-stalled-debug-5000436.md`. The last report is especially important: committed generation 9 was recoverable while unfinished generation 10 was disposable, matching the authority document, but its 2,048-rank collective membership was not resilient-pool conformance.

## Bounded successor tasks

Create these as separate WG tasks after this document is merged. Every task must paste the authority conformance checklist into `## Validation`, cite its R-IDs, and avoid a broad rewrite.

1. **Frontier admission lease adapter (R01, R07).** Implement acquire/renew/expire/takeover and stale-writer CAS tests using one approved durable control mechanism. Include loser-exits-successfully-before-model-load and checkpoint-publication fencing. Scope: new lease module plus focused tests only.
2. **Membership/lifecycle controller (R02, R03, R11, R14).** Implement stable peer identity, random incarnation, READY leases, lifecycle transitions, active snapshots, and stage deadlines independently of Slurm rank count. Scope: control records/controller/tests, no tensor transport changes.
3. **Contribution identity and close policy (R04, R06).** Add contribution sequence/idempotent receipt semantics, accepted-token floor, capped READY fraction, deterministic freeze, and deadline defer/abort records. Scope: protocol metadata/policy tests.
4. **Production shard plan and exact tensor reducer (R05, R08, R15).** Bind full E97 layout to deterministic owners, bounded chunks and stable accumulation; compare changing-weight results against a float64 reference. Scope: reducer/codec/reference tests, no launcher.
5. **Owner reassignment and redistribution (R08, R11, R14).** Integrate retained-chunk replay, owner death, committed shard redistribution, catch-up, backpressure, and prompt release. Scope: network harness plus failure tests.
6. **Fenced global commit/checkpoint integration (R07, R12, R14).** Assemble all shards and required outer state into one immutable commit, accepted-token clock, and fresh-allocation resume under a newer lease. Scope: runtime/checkpoint integration tests.
7. **Deterministic 2-node lifecycle gate (R01–R16 as applicable).** Script slow boot, late join, peer disappearance with continued commits, new-incarnation rejoin, stale/duplicate rejection, owner loss, quorum-collapse pause, and fresh-allocation continuation. It must inspect committed manifests, not only logs. Scope: test harness/fixture; do not launch scale jobs.
8. **Frontier 2-node runner admission.** Only after task 7 passes locally, run the same gate on Frontier and register manifests, resource bounds, and exact commands. No 4+ node task may depend directly on an unpassed implementation task.
9. **Scale ladder tasks.** One task per rung (4, 8, 32, 64, 256+), each depending on the prior accepted rung and measuring bounds/numerics/failures. A future system-scale single allocation uses the same sequence; simultaneous-allocation federation requires its own ADR first.
10. **Training-policy research gate (R15).** Choose production `Q_min`, `T_min`, schedules, checkpoint cadence, and outer optimizer using changing-participation convergence experiments. Any `tau > 0` work is a separate experimental task and policy version.
