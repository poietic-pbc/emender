Companion to the authoritative [Resilient DiLoCo Compute Pool](RESILIENT_DILOCO_COMPUTE_POOL.md), version 1, and its normative [Native resilient DiLoCo data plane v1](NATIVE_RESILIENT_DILOCO_DATAPLANE.md) specialization. This file records the post-integration local/runtime state on 2026-07-19; it is not a second design. Status is **present**, **partial**, or **gap**. Line numbers are deliberately avoided because the implementation is moving; paths and test names are stable review anchors. “Present” means the requirement is wired into the live split-role code path and locally exercised; it does not claim that a downstream real-model Frontier gate has run. R01–R16 trace the compute-pool semantics; NDP01–NDP17 trace the required production native path.

## Current architecture boundaries

The legacy `train.py` DiLoCo merge and compiled MPICH scale path remain numerical/performance references, but their process groups/collectives and launched-rank assumptions are nonconforming for resilient global membership. The split-role Python TCP/file implementation remains an explicit small debug fixture. Production selects the separate native branches: one persistent compiled service, one model-free manager, eight direct-memfd trainers and compiled point-to-point owner transfer per node. `QuorumTransportServer` and its node-0 transport remain adjacent legacy/reference code and are not production backends.

Historical evidence still includes `docs/ASYNC_QUORUM_DILOCO.md`, the July 14–17 Frontier reports, and the recoverable-generation-9/disposable-generation-10 observation. Current implementation evidence is `reports/integrate-resilient-pool-v1-20260718.md` plus its committed metrics JSON. No Frontier job result is claimed by this integration task.

## Bounded successor tasks

The original ten-task implementation backlog produced the modules now integrated above. The remaining bounded work is operational/research work and must keep the authority conformance checklist in `## Validation`.

1. **Validate two-node native pool startup (R02/R03/R09/R13/R14/R16; NDP01–NDP17).** Exercise the exact integrated commit and topology without launching real E97 work.
2. **Qualify the Frontier durable control store (R01/R07/R10).** Prove the selected SQLite path's locking/durability/takeover semantics or substitute an approved CAS backend without changing the protocol.
3. **Run native real-2n, resilience, and fresh-allocation gates (R01–R16; NDP01–NDP17).** Only after exact-code G2, run G3–G5 and inspect committed manifests, restart fences, checkpoint reloads, bounds, and native telemetry.
4. **Scale ladder tasks (R16/NDP17).** Run G6 one accepted rung at a time (4, 8, 32, 64, 256+), each depending on the prior rung and measuring bounds, numerics, failures, and the fixed-world performance reference.
5. **Training-policy research gate (R06/R15).** Choose production `Q_min`, `T_min`, schedules, checkpoint cadence, and outer optimizer under changing participation. Any `tau > 0` work remains a separate ADR/policy.
6. **Backend conformance fixture (R13/NDP03).** Add a hyperscale-local provider/adapter test using the same control/owner protocol without weakening exact-CXI Frontier selection.
