# Resilient DiLoCo traceability and bounded backlog

Companion to the authoritative [Resilient DiLoCo Compute Pool](RESILIENT_DILOCO_COMPUTE_POOL.md), version 1, and its normative [Native resilient DiLoCo data plane v1](NATIVE_RESILIENT_DILOCO_DATAPLANE.md) specialization. This file records the post-audit local/runtime state on 2026-07-18; it is not a second design. Status is **present**, **partial**, or **gap**. Line numbers are deliberately avoided because the implementation is moving; paths and test names are stable review anchors. “Present” means the requirement is wired into the live split-role code path and locally exercised; it does not claim that a downstream Frontier gate has run. Component-only native mechanisms are explicitly **partial** or **gap**, even when their isolated G0 tests pass. R01–R16 trace the compute-pool semantics; NDP01–NDP17 trace the required production native path.

## Current architecture boundaries

The legacy `train.py` DiLoCo merge and compiled MPICH scale path remain numerical/performance references, but their process groups/collectives and launched-rank assumptions are nonconforming for resilient global membership. The split-role Python TCP/file implementation is still the only wired dense role path. It is a debug fixture, not a production backend. Native artifact/provider attestation alone cannot change that fact: both native selections now fail closed inside the role before model load. The component local/fabric ABIs may become the production path only after `implement-live-split` replaces `LocalTrainerSpool`, `DistributedOwnerServer`, `submit_owned_shards` and `fetch_owned_shards`, supplies a cross-process local ABI, and passes the exact full-layout accounting. `QuorumTransportServer` and its node-0 transport remain adjacent legacy/reference code and are not production backends.

Historical evidence still includes `docs/ASYNC_QUORUM_DILOCO.md`, the July 14–17 Frontier reports, and the recoverable-generation-9/disposable-generation-10 observation. Current implementation evidence is `reports/integrate-resilient-pool-v1-20260718.md` plus its committed metrics JSON. No Frontier job result is claimed by this integration task.

## Bounded successor tasks

The original ten-task implementation backlog produced the modules now integrated above. The remaining bounded work is operational/research work and must keep the authority conformance checklist in `## Validation`.

1. **Implement live split-role native dense wiring (`implement-live-split`; R03–R10/R13–R16; NDP01–NDP17).** Replace every live Python dense/spool call, add the cross-process trainer/manager local boundary and native send/receive bridge, account full-E97 lanes/results/registered pools, and keep production fail-closed until end-to-end fault tests pass.
2. **Run G1 singleton CXI service qualification (R03/R10/R13/R14/R16; NDP02/NDP03/NDP07/NDP13/NDP14/NDP16/NDP17).** Only after live integration, retain exact source/bundle/provider/endpoint artifacts for that commit.
3. **Run G2 two-node synthetic full-layout qualification (R03–R06/R08/R10/R11/R13–R16; NDP01–NDP17).** Attest the exact E97 byte flow, bounds, releases, failure cases and zero-fallback counters required by `validate_g2_gate`.
4. **Qualify the Frontier durable control store (R01/R07/R10).** Prove the selected SQLite path's locking/durability/takeover semantics or substitute an approved CAS backend without changing the protocol.
5. **Run native real-2n, resilience, and fresh-allocation gates (R01–R16; NDP01–NDP17).** Only after exact-code G2, run G3–G5 and inspect committed manifests, restart fences, checkpoint reloads, bounds, and native telemetry.
6. **Scale ladder tasks (R16/NDP17).** Run G6 one accepted rung at a time (4, 8, 32, 64, 256+), each depending on the prior rung and measuring bounds, numerics, failures, and the fixed-world performance reference.
7. **Training-policy research gate (R06/R15).** Choose production `Q_min`, `T_min`, schedules, checkpoint cadence, and outer optimizer under changing participation. Any `tau > 0` work remains a separate ADR/policy.
8. **Backend conformance fixture (R13/NDP03).** Add a hyperscale-local provider/adapter test using the same control/owner protocol without weakening exact-CXI Frontier selection.
