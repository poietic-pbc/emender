# Resilient DiLoCo traceability and bounded backlog

Companion to the authoritative [Resilient DiLoCo Compute Pool](RESILIENT_DILOCO_COMPUTE_POOL.md), its normative [Native resilient DiLoCo data plane v1](NATIVE_RESILIENT_DILOCO_DATAPLANE.md) specialization, and the reviewed [bounded-lag asynchronous DiLoCo v2 policy](ASYNC_DECOUPLED_DILOCO_V2.md). This file records the post-integration v1 local/runtime state and the locally implemented, not-yet-Frontier-qualified v2 state as of 2026-07-24; it is not a second design. Status is **present**, **partial**, or **gap**. Line numbers are deliberately avoided because the implementation is moving; paths and test names are stable review anchors. “Present” means the requirement is wired into the live split-role code path and locally exercised; it does not claim that a downstream real-model Frontier gate has run. R01–R16 trace the compute-pool semantics; NDP01–NDP17 trace the required production native path; V2A01–V2A18 trace only the bounded-lag extension.

## Current architecture boundaries

The legacy `train.py` DiLoCo merge and compiled MPICH scale path remain numerical/performance references, but their process groups/collectives and launched-rank assumptions are nonconforming for resilient global membership. The split-role Python TCP/file implementation remains an explicit small debug fixture. Production selects the separate native branches: one persistent compiled service, one model-free manager, eight direct-memfd trainers and compiled point-to-point owner transfer per node. `QuorumTransportServer` and its node-0 transport remain adjacent legacy/reference code and are not production backends.

`docs/ASYNC_QUORUM_DILOCO.md`, `LocalAsyncDilocoConfig`, and the existing core
tests remain v1 stale-reject reference/scaffolding, not authority for v2.
ADR-002 is the policy authority. Current v1 implementation evidence is
`reports/integrate-resilient-pool-v1-20260718.md` plus its committed metrics
JSON. The retained job 5062348 report is in Git commit `20c9d1be`; it is
evidence of five atomic generations and a failed overlap/cadence/idle gate, not
v2 acceptance.

## Bounded successor tasks

The original ten-task implementation backlog produced the modules now integrated above. The remaining bounded work is operational/research work and must keep the authority conformance checklist in `## Validation`.

1. **Qualify v2 at exactly two nodes (R01–R16; NDP01–NDP17; V2A01–V2A18).** Run numerical, failure/restart, real-decoupling performance, and convergence/reproducibility gates under explicit `Partition=batch`, `QOS=debug`.
2. **Qualify the Frontier durable control store (R01/R07/R10/V2A14/V2A17).** Prove the selected SQLite path's locking/durability/takeover semantics or substitute an approved CAS backend without changing the protocol.
3. **Review promotion only after accepted v2 two-node artifacts (R16/NDP17/V2A18).** No 4+ node v2 task is authorized by this ADR or matrix.
4. **Backend conformance fixture (R13/NDP03/V2A15).** Add a hyperscale-local provider/adapter test using the same control/owner protocol without weakening exact-CXI Frontier selection.
