## Current architecture boundaries

The legacy `train.py` DiLoCo merge and compiled MPICH scale path remain numerical/performance references, but their process groups/collectives and launched-rank assumptions are nonconforming for resilient global membership. The live split-role entrypoint now selects `ndm/resilient_pool_runtime.py` after local K40 training: managers register leased READY incarnations, freeze contribution metadata, send full-layout shards directly to distributed owners, and redistribute committed chunks. `QuorumTransportServer` and its node-0 transport remain adjacent legacy/reference code and are no longer imported by `scripts/frontier/resilient_e97_role.py`.

Historical evidence still includes `docs/ASYNC_QUORUM_DILOCO.md`, the July 14–17 Frontier reports, and the recoverable-generation-9/disposable-generation-10 observation. Current implementation evidence is `reports/integrate-resilient-pool-v1-20260718.md` plus its committed metrics JSON. No Frontier job result is claimed by this integration task.

## Bounded successor tasks

The original ten-task implementation backlog produced the modules now integrated above. The remaining bounded work is operational/research work and must keep the authority conformance checklist in `## Validation`.

1. **Qualify the Frontier durable control store (R01/R07/R10).** Prove the selected SQLite path's locking/durability/takeover semantics or substitute an approved CAS backend without changing the protocol.
2. **Run the Frontier 2-node gate (R01–R16).** The downstream task runs the 20m first-generation gate, then the approved 30m resilience and 20m newer-fence restart gates; it must inspect committed manifests and stage telemetry. This task submitted no job.
3. **Scale ladder tasks (R16).** One accepted rung at a time (4, 8, 32, 64, 256+), each depending on the prior rung and measuring bounds/numerics/failures.
4. **Training-policy research gate (R06/R15).** Choose production `Q_min`, `T_min`, schedules, checkpoint cadence, and outer optimizer under changing participation. Any `tau > 0` work remains a separate ADR/policy.
5. **Backend conformance fixture (R13).** Add a hyperscale-local adapter test using the same control/owner protocol.
