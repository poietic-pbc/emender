# EMENDER E97 → 35B MoE implementation

**Status:** implementation in progress. Exact graph inspection and the fused
Triton forward kernel foundation are implemented. Fused backward, optimizer,
and node-local communication remain incomplete, so no MoE parity experiment,
training, or Slurm launch is authorized by this document.

## Authorities and boundaries

This recipe uses the user's E97→35B MoE plan and the actual instantiated E97
module graph. Frontier execution remains governed by
`RESILIENT_DILOCO_COMPUTE_POOL.md` ADR-003 and
`RESILIENT_DILOCO_GAP_MATRIX.md`.

For a future production runner, applicable requirements are R07, R12,
R14/NDP13, R16, and the checkpoint-atomicity clause of NDP15. NDP02 and NDP17's
elastic-native scale chain are explicitly retired for ADR-003 production;
R02–R06/R08–R11, V21S01–V21S17, and ISP01–ISP07 are not claimed by this local
model implementation. A 256-node run remains review-only and must not be
inferred from this recipe.

Only `layers.*.mlp` may be replaced. The recurrent mixers, matrix-state update,
Q/K/V projection, erase/write and output gates, recurrent output projection,
embeddings, and recurrent norms remain unchanged.

## Non-negotiable fused-kernel gate

No parity experiment, debug submission, training, or performance claim is
admissible until routing, expert forward/backward, node-local dispatch/combine,
and optimizer execution are fused and fail closed. The Python MoE module is a
CPU-only construction/counting oracle and now aborts if called on a GPU.
Frontier execution must use `ndm/triton/e97_moe_fused.py`; there is no eager
fallback, and its training entry point deliberately aborts until backward and
optimizer kernels are complete.

## Implemented now

`ndm/triton/e97_moe_fused.py` currently provides real ROCm Triton kernels for:

- FP32 router GEMM;
- fused top-3 selection, selected softmax, counts, probability sums, z-loss,
  entropy, and maximum probability;
- padded expert prefix layout and atomic dropless assignment;
- token packing into bounded buffers;
- grouped fused gate/up expert GEMMs;
- fused SiLU multiplication;
- grouped down-projection GEMMs;
- deterministic top-3 weighted combination; and
- strict GPU/HIP/BF16/FP32 ABI validation with no eager fallback.

These kernels have executed successfully on a gfx90a MI210 under the canonical
Frontier ROCm 7.1 / PyTorch 2.10 / Triton 3.6 environment. This is not yet a
training-ready implementation: fused backward, fused optimizer, shared-expert
fusion, and eight-GCD RCCL dispatch are still mandatory.

`ndm/models/e97_moe.py` provides CPU-only structural scaffolding:

- one shared and 64 routed bias-free SwiGLU experts;
- dropless token-level top-k routing;
- FP32 router logits and softmax;
- selected weights renormalized to exactly one;
- load-balancing and z-loss tensors with configurable coefficients;
- token counts/fractions, entropy, maximum probability, co-selection matrix,
  selected-weight normalization error, and dropped-token metrics;
- deterministic contiguous Frontier ownership (`0–7`, ..., `56–63`);
- function-preserving widening, cloning, and one-half down-projection scaling;
- replacement of only the instantiated E97 post-mixer FFNs;
- exact recipe calculation from unique parameters in the live graph.

This structural reference is not an admissible GPU execution or experiment
path. It is not the eight-way RCCL expert-parallel transport.
