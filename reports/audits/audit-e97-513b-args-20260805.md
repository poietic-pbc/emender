## Checkpoint Metadata Limits

The checkpoint payload written by `train.py` stores:

```text
'step'
'model_state_dict'
'optimizer_state_dict'
'loss'
```

and conditionally stores:

```text
'checkpoint_metadata'
'diloco_outer_state'
```

See `train.py`, lines 939-955. The periodic/final metadata includes a
`model_variant` string and model totals (`train.py`, lines 2961-2974 and
3098-3106), but not the full immutable training argument namespace.

The E97 loader therefore requires external configuration. In `ndm/e97.py`,
`e97_checkpoint_config()` first checks embedded `args`/`config`/`cfg`, then
requires an adjacent `args.json` or a caller-provided `args_json`; if absent it
raises:

```text
E97 checkpoints require their training arguments. Place args.json beside ...
```

The loader then reconstructs model kwargs from that config. Decisive external
architecture fields consumed there include `dim`, `depth`, `n_groups`,
`n_state`, `n_slots`, `n_heads`, `use_gate`, `gate_activation`, `linear_state`,
`use_write_gate`, `use_chunked_e97`, `e97_chunk_size`, `state_expansion`,
`use_triton`, `mlp_ratio`, and `mlp_multiple` (`ndm/e97.py`, lines 107-168).

Tensor shapes in `model_state_dict` can reflect whether MLP tensors exist, and
the validation report lists representative `layers.0.mlp.*` tensors for the
150B/staged lineage, but checkpoint shape inspection is not enough to recover
all semantic training args. The loader design confirms that `args.json` or an
equivalent manifest is part of the loadable artifact.
